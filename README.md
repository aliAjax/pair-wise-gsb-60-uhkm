# 医疗器械上市后安全信号核查与处置平台

面向医疗器械上市后安全团队的本地工作台，用于合并投诉、维修、不良事件和现场报告，维护证据矩阵、调查任务、风险状态、结论版本和审计轨迹。

## 技术栈

- SvelteKit 2 + Vite + TypeScript
- Skeleton UI + Tailwind CSS
- Svelte stores
- SvelteKit Form Actions
- TanStack Query for Svelte
- Zod

## 主要工作区

- `/`：开放信号、高风险信号、任务和逾期总览
- `/signals`：关键词与多条件筛选、人工登记新信号
- `/signals/[id]`：证据矩阵、状态流转、补充证据、结论版本、重新打开和审计
- `/trends`：发生率趋势与阈值核对
- `/batches`：批号覆盖与报告追踪
- `/audit`：跨信号审计时间线和 JSON 报告导出

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18460`。

## 构建与检查

```bash
npm run check
npm run test   # 重算流水线：去重、存档重试、断点续算、复核换版
npm run build
```

无后端服务，页面使用确定性模拟数据，并将信号、证据、读数版本、重算作业和审计记录持久化到浏览器 `localStorage`。关键表单先经过 SvelteKit Form Action 与 Zod 校验，再写入本地 store。

## 证据更正与读数重算（可恢复流程）

台账、批次追踪、趋势核对三处统一读取 `signal.readings`（不可变读数版本），不再各读散落的顶层字段。证据被安全团队更正时：

1. **证据更正**：旧证据标记 `superseded` 但不删除，原始字段、更正原因、操作人完整保留，新证据接续。
2. **读数失效**：更正瞬间创建持久化重算作业，三处页面继续展示**上一版完整结果**，并用徽标/横幅标明「重算未完成（上一版）」。
3. **检查点重算**：依次完成 台账读数 → 批次覆盖 → 趋势核对 → 版本存档；候选版本在趋势核对后冻结。
4. **并发只受理一个**：同一信号的重算经 Web Locks 跨窗口互斥（无该 API 时退化为持久化作业表），两个窗口同时提交只跑一个，后到提交登记进 `job.attached` 并入等待。
5. **存档失败可恢复**：前两次存档确定性失败以演示重试——旧结果保留、候选版本与已完成检查点不丢，自动退避后只重试存档；刷新页面时 `AppShell` 扫描未完成作业，从最后一个检查点续算。
6. **复核确认换版**：复核人在信号详情页比对前后读数并确认后，台账、批次、趋势三处原子一起换读；旧版进入 `readingsHistory`，逐字段前后值与两版取数依据写入审计。

# 医疗器械上市后安全信号核查与处置平台

面向医疗器械上市后安全团队的本地工作台，用于合并投诉、维修、不良事件和现场报告，维护证据矩阵、调查任务、风险状态、结论版本和审计轨迹。

## 技术栈

- SvelteKit 2 + Vite + TypeScript
- Skeleton UI + Tailwind CSS
- Svelte stores
- SvelteKit Form Actions
- TanStack Query for Svelte
- Zod

## 主要工作区

- `/`：开放信号、高风险信号、任务和逾期总览
- `/signals`：关键词与多条件筛选、人工登记新信号
- `/signals/[id]`：证据矩阵、证据更正、状态流转、补充证据、结论版本、重算与换版确认、重新打开和审计
- `/trends`：发生率趋势与阈值核对（读取已发布读数版本）
- `/batches`：批号覆盖与报告追踪（读取已发布读数版本）
- `/audit`：跨信号审计时间线和 JSON 报告导出

## 证据更正 → 读数失效 → 重算 → 复核换版（可恢复流程）

安全团队更正证据后，台账、批次追踪、趋势核对三处不再各读各的旧数字，而是接入同一套可恢复流程：

1. **更正留痕**：在 `/signals/[id]` 的证据矩阵中点「更正记录」，系统保存更正前后的全部字段（含归因报告数）与更正依据，不静默覆盖。
2. **先失效再重算**：更正提交后立即对该信号的受影响读数登记失效，并受理一个重算作业，按「受影响信号读数 → 批次覆盖 → 趋势核对」三阶段顺序重算；每阶段独立存档。
3. **上一版继续展示**：重算完成前（以及完成但未复核前），三个页面继续给出上一版**完整**结果，并统一标注「上一版 V* · 重算未完成」。
4. **并发单例**：两个窗口同时对同一信号提交重算，只受理一个作业；后到的请求并入现有作业（作业内记录受理窗口与并入窗口）。窗口崩溃/刷新后，租约过期的作业由新窗口自动接管，未完成阶段接着算。
5. **存档失败可重试**：阶段或候选结果存档失败时保留旧结果与已完成进度，按固定间隔自动重试，已存档阶段不重算。可在重算面板点「演练：注入 2 次存档失败」验证。
6. **复核确认三处一起换版**：三阶段产出候选结果后，复核人在对比表中确认，台账、批次覆盖、趋势在同一次操作切换到新版本号，并在审计中分别留下三处的「旧读数 → 新读数」依据；导出的 JSON 报告包含已发布读数版本、失效状态与更正历史。

相关实现：

- `src/lib/models/recalc.ts`：更正、失效、作业、读数版本模型与表单校验
- `src/lib/services/recalc-compute.ts`：确定性重算规则（报告数、发生率、批次覆盖、趋势）
- `src/lib/services/recalc-store.ts`：单例作业、租约/心跳、失败重试、跨窗口同步、确认换版
- `src/lib/components/RecalcPanel.svelte`：阶段进度、并发/失败演练、复核确认面板
- `src/lib/components/ReadingVersionBadge.svelte`：三处共用的读数版本/未完成标识

端到端验证（覆盖更正失效、并发并入、存档失败重试续算、确认三处换版与审计依据）：

```bash
npm run verify:recalc
```

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18460`。

## 构建与检查

```bash
npm run check
npm run build
npm run verify:recalc
```

无后端服务，页面使用确定性模拟数据，并将信号/证据/版本/审计（`medical-safety-signals-v2`）与读数版本、重算作业、失效登记持久化到浏览器 `localStorage`。关键表单先经过 SvelteKit Form Action 与 Zod 校验，再写入本地 store。
